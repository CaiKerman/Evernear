## 当前支持路径

高级槽位的**实时接收会话**在接管后直接接收后续原始麦克风，基础接收会话关闭；高级负责该段交流的介入、任务和退出判断。该方案不是旧版“基础永远收音、高级只读文字”。

为保持四厂商一致的介入授权边界，接收/控制与获准后的语音回答使用隔离会话，均使用同一槽位的接口、模型和音色。高级接收会话持续存在，音频回答会话按轮建立。并非“一条 WebSocket 同时输出可靠 JSON 控制和口语”。一次有效输入通常包含一次判断生成及一次回答生成；firstAnswer 可与 JSON 一起提供，但其音频合成仍需一次播报请求。没有额外的评价首答/摘要模型调用。

高级待命没有音频输入、没有用户 complete turn、没有 response.create。首答、高级连接、必要文字请求在批准后并行；首答足够则撤销待命。远端是否计算配置、产生驻留费以及本地未播放的判断音频是否收费，需要真实账单核查，**不宣称待命免费或服务端没有音频生成**。

第一轮只用有界文字交接：原话、意图/语气推断、播放状态、任务 ID/修订号及必要上下文。旧的部分播放注明边界未知。交接 JSON 按完整字段裁剪，不截断成损坏 JSON。原音不缓存、不回放、不转传；后续实时音频才交给高级。原始背景声音既已发送到当前接收方，可能留在服务商远端会话；本地不入有效历史不等于服务商没有收到。

转写仅支持 Qwen 协议中固定的 `input_audio_transcription.model=qwen3-asr-flash-realtime`，这是该协议内置的可选 ASR 子能力，可能另行计费；不改用户主语音模型、不新增必填配置。服务端不支持该字段时直接失败，不删除字段或改模型重试。其他厂商明确显示暂不支持；现有回答器不是保证逐字准确的专用 TTS，真实朗读保真度待验收。

## 内部时间与生命周期

- 连接配置沿用 20 秒握手超时；每次高级待命/回交最多保留 45 秒，超时关闭候选、保留原接收方，不自动重建。
- 交接要等生成、实际播放回执、介入决定和当前讲话结束。另用当前 PCM 能量作保守保护：RMS > 0.015 后至少 800ms 不交接，弥补服务端 VAD 事件传输延迟。不是语义 VAD，噪声可能延迟交接，需实机调校。
- 不因单次沉默自动退出。当前接收模型给出 ambient 决定或用户点击返回才回交；“嗯/对”用 ack，不取消声音/任务。
- 修订用 700ms 合并窗口，保留连续补充，只对最终条件请求一次；单文字槽仍共享占用。
- 主动录音最多 90 秒，结束后等转写最多 15 秒。录音与回答/交接互斥；全局暂停撤销录音，结束录入不恢复已被暂停的会话。
- 高级接管后故障不自动重试，显示无接收方。基础原有重连仍按 3—30 秒退避，仅在基础值守且 running 时执行，暂停清理定时器；没有新增恢复循环。
- `voice-transition` 日志只存版本、阶段、槽位、耗时，无交接正文或密钥。成本仍以服务商用量报告及用户价格为准，未报告部分未知。
